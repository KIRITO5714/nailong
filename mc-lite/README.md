# 方块世界 mc-lite

一个 2D 侧视的简易「我的世界」：挖方块、捡物品、放方块、合成工具、按工具等级解锁更硬的矿石。
在此之上加了两层自己的特色：**地下邮局限时委托**（交货换稀有酬劳）和**松散方块塌方**（沙/碎石挖空下方会整列坠落的物理）。
画风是代码绘制的 16×16 像素贴图，不依赖任何外部美术素材。

- 后端：Spring Boot 3.3 + Java 21 + Spring Data JPA + H2（文件库）
- 前端：Vue 3 + TypeScript + Vite 5 + Pinia + Canvas 2D
- 规则全部写在 `server/src/main/resources/content.json`，改方块/配方不用改 Java 代码

## 目录

```
mc-lite/
├─ server/          Spring Boot 后端（世界生成、玩法判定、存档）
│  └─ src/main/resources/content.json   方块/物品/工具/配方表
├─ web/             Vue 3 前端（渲染、物理、交互、合成面板）
└─ docs/架构说明.md  分层理由、协议、实测记录与已知限制
```

## 运行

需要本机已安装：**JDK 21**、**Maven 3.9+**、**Node 18+**。

```bash
# 1) 后端（默认 8080，存档写到 server/data/mclite.mv.db）
cd server
mvn spring-boot:run

# 2) 前端（默认 5173，/api 已代理到 8080）
cd web
npm install
npm run dev
```

打开 http://localhost:5173 ，输入世界名（种子可留空）→ 创建世界 → 开挖。
世界列表里的存档会持久化，关掉浏览器再进来还在。

跑测试：

```bash
cd server && mvn test     # 28 个用例：世界生成 7 + 玩法/塌方/委托 21
cd web && npm run build   # vue-tsc 类型检查 + 生产构建
```

## 操作

| 动作 | 键盘 | 触屏 |
| --- | --- | --- |
| 左右走 | `A` `D` / `←` `→` | 左下方向键 |
| 跳 | `W` / `↑` / `空格` | 右下跳跃键 |
| 挖 / 放 | 按住方块（挖）；选中可放置物品后点空格（放） | 同左，直接点画布 |
| 切换挖掘/放置 | `Q` | 点物品栏里的方块 |
| 合成面板 | `E` | 顶栏「合成」 |
| 地下邮局委托 | `F` | 顶栏「委托」 |
| 选物品栏 | `1`–`9` | 点格子 |
| 关闭面板 | `Esc` | 点面板外 |

挖掘要**按住**：进度条走满才掉物品，松手就作废。够不着（>5 格）、工具等级不够、基岩，都会当场给红色/灰色提示框。

## 玩法

- 15 种方块：草、泥土、石头、木头、树叶、煤/铁/金/钻石矿、基岩、木板、工作台，以及**沙、碎石、荧光晶**。
- 工具等级 = 背包里最高级的镐，自动生效，不用装备：徒手 T0 → 木镐 T1 → 石镐 T2 → 铁镐 T3 → 钻石镐 T4。
  石头要 T1，铁矿要 T2，金矿/钻石矿要 T3；等级不够挖不动，速度也随等级提升（1.0 / 1.6 / 2.4 / 3.4 / 4.8）。
- 6 个配方：木头→木板×4、木板×4→工作台（这两个随身可做）；木/石/铁/钻石镐必须**站在工作台 5 格内**。
- 世界 160×96，同一种子生成完全一样的地形：地表起伏、地下矿脉（越深越稀有）、树、出生点清空；浅层埋有沙袋、深层有碎石脉。
- **塌方物理**：沙和碎石是松散方块，挖空它们下方（或挖掉承重的柱子）会整列往下坠，直到落到实心方块上；泥土/石头有黏聚力不会坠。
  塌方埋到玩家时，服务端会把玩家顶到堆顶并下发坐标，客户端同步 teleport，避免物理和存档各说各话。
- **地下邮局委托**：开局 3 张限时单（要某材料 N 个 → 酬荧光晶等）。倒计时归零自动换单；交付扣材料发酬劳并补一张新单。
  荧光晶只有邮局给，放在洞里会照亮周围（叠加在玩家光照之上），深处不再只靠身边那一圈光。
- 往下挖会进入洞穴光照：离玩家越远越暗，深处几乎全黑。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/content` | 方块/物品/工具/配方表 + 简化说明 |
| GET | `/api/worlds` | 存档列表 |
| POST | `/api/worlds` | 创建（name, seed） |
| GET | `/api/worlds/{id}` | 读档：方块、背包、玩家坐标 |
| DELETE | `/api/worlds/{id}` | 删档 |
| POST | `/api/worlds/{id}/mine` | 挖（x, y） |
| POST | `/api/worlds/{id}/place` | 放（x, y, item） |
| POST | `/api/worlds/{id}/craft` | 合成（recipe） |
| POST | `/api/worlds/{id}/move` | 上报玩家坐标 |
| GET | `/api/worlds/{id}/orders` | 委托板（惰性清理过期单并补新单）+ 服务端当前时间 |
| POST | `/api/worlds/{id}/deliver` | 交付委托（orderId），扣材料发酬劳并换单 |

所有玩法判定都在服务端，客户端只做预测和表现；失败统一返回 `{code, message}`（400/404）。

## 简化与已知限制（如实说明）

- 矿石直接掉锭，**没有熔炉和燃料**；镐不用木棍；树叶不掉东西也不掉树苗。
- 工具等级自动取最高镐，没有装备/耐久系统。
- **塌方只作用于沙/碎石这类松散方块**；泥土、石头有黏聚力，挖空下方也不会坠（否则竖井没法挖）。
- **委托是惰性结算**：不开后台线程/定时器，每次读档或请求委托板时清理过期单、去重标题并补满 3 张；倒计时用服务端时间 offsets 校准。
- 单人本地存档，**没有联机、没有账号**；H2 文件库单进程使用，不适合多实例部署。
- 物理（重力、碰撞、跳跃）在客户端算，服务端只记录坐标并做范围裁剪——作弊改坐标不影响挖掘/合成判定，但位置本身不是强校验。
- 移动端触屏布局按 CSS 媒体查询（`hover: none` / `pointer: coarse`、宽度 ≤640px）实现，开发期只在桌面浏览器验证过完整流程，**没有在真机上实测**。
