# 架构说明

## 1. 为什么这样分层

```
web (Vue3 + Canvas)              server (Spring Boot)
  渲染 / 玩家与怪物模拟 / 挥砍命中 ──►  掉落表 / 合成 / 悬赏结算 / 存档
  只信服务端返回的 mutation          唯一权威：这只怪死了给什么、够不够做剑、悬赏能不能交
```

- **经济规则放服务端**：掉落表、材料数量、配方、悬赏击杀数与酬劳，这些是「游戏规则」，放前端等于把规则交给玩家改。
- **逐帧模拟放客户端**：怪物走位/追击/接触伤害、玩家重力碰撞、挥砍命中判定每帧都要算，走 HTTP 会卡成幻灯片。
  客户端判命中后只上报一句「这只怪死了」（`POST /loot`），服务端按 `content.json` 的掉落表结算材料并累计击杀数。
  **这是本版最大的信任边界**：改客户端内存可以伪造击杀刷材料。单机本地存档没有对抗需求，所以接受这个取舍，
  服务端仍做了两道兜底——未知怪物 key 直接拒（`UNKNOWN_MOB`），两次上报间隔 <250ms 拒（`LOOT_TOO_FAST`），避免手滑或脚本一秒刷几十只。
- **内容表驱动**：`content.json` 是方块、物品、武器、配方、怪物、悬赏模板的唯一来源，`ContentRegistry` 启动时读一次。
  加一种怪或调一个伤害只动 JSON；前端从 `/api/content` 拿同一份表来画贴图、算挥砍射程/冷却、列合成与悬赏面板，两边不会各写一套数值。
  怪物表里的 `w/h/color/accent/weight` 是**只给客户端用的表现与刷怪权重字段**，服务端 record 不声明它们，Jackson 直接忽略。

## 2. 世界怎么存

- 内存里是 `int[] blocks`，行主序：`index = y * width + x`，0 表示空气。`World` 只负责取/放/边界。
- 落库时一个方块编码成一个字符（`'A' + id`），480×96 的世界就是 46080 个字符，存 `@Lob` 字段（约 45KB 文本），读写都是 O(n) 一遍扫。
- **地表线单独存一列**（`surfaceLine`，每列一个字符，480 字符刚好在 `length = 512` 限制内）。
  这是上一版修 bug 修出来的设计：树冠会盖在树干旁边，如果「地表」按每列第一个实心方块算，天空/地下的分界线会跟着树长歪。
  本版它还有第二个用途——**刷怪器直接查 `surface[x]` 就知道该列地面在哪**，不用每帧向下扫描。
- **世界不可挖掘 ⇒ 方块数组是只读的**：没有 `/mine`、`/place`，服务端也不再需要塌方、埋人顶起、工具等级、reach 这些判定，
  相关代码整段删掉而不是留开关。地下层照样生成（矿脉、沙囊、碎石、基岩），只是玩家永远到不了，属于「留着的风景」。
- 存档实体 `WorldEntity`：名字、种子、宽高、方块串、地表线、背包 JSON、击杀数 JSON（`killsJson`，`@Lob`）、玩家坐标、
  血量 `playerHp`、悬赏板 `ordersJson`、自增序号 `orderSeq`、时间戳。H2 文件库 `./data/mclite`，`ddl-auto=update`。
  `orderSeq` 和 `playerHp` 故意用**可空 `Integer`**：旧存档没有这两列，Hibernate 对非空表 `ALTER ADD COLUMN NOT NULL` 会失败；
  可空列 + 代码侧 `null→0` / `null→满血` 才能平滑升级旧档。旧档里的旧委托标题在读档时会被 `Bounties.refresh` 当成未知标题清掉换新单。
  内容表里保留 `workbench` 方块定义同理：新版既不生成也不需要它（合成随身可做），留着只是为了让挖掘版旧档里已放置的工作台还能正常渲染。

## 3. 服务端判定顺序

每个世界一把锁（`synchronized (lock(id))`），同一世界的击杀/合成/交付/移动串行，避免两个请求同时扣同一份材料或同一份击杀数。

- `loot(mob)`：怪物 key 在表里 → 距上次上报 ≥250ms → `kills.merge(mob, +1)` → `Loot.roll` 按掉落表逐项 `chance/min/max` 掷 → 加材料 → 返回 `Mutation`（含刷新后的悬赏板）。
- `craft(recipe)`：配方存在 → 材料够（`NO_MATERIAL`）→ 扣材料加产物 → 若产物是更高级的剑，武器等级自动抬升并在 message 里说明。
- `bounties()`：`Bounties.refresh` 惰性清理 + 补满 3 张，返回悬赏板和服务端当前时间。
- `deliver(bountyId)`：单号存在 → 未过期（`BOUNTY_EXPIRED`）→ 各怪击杀数够（`NOT_ENOUGH_KILLS`）→ 扣 `wants` 加 `reward` → 移除该单 → 补新单。
- `move(x, y, hp)`：坐标裁剪到世界范围，血量裁剪到 0..100，纯存档用，不做合法性校验。

失败抛 `GameException(code, message)`，`ApiExceptionHandler` 统一转成 400（规则不满足）或 404（世界不存在），前端直接显示 message；
`LOOT_TOO_FAST` 在前端被静默吞掉——那是挥砍冷却的正常副产物，不该弹红框打扰玩家。

## 4. 前端结构

- `stores/game.ts`（Pinia）：世界、背包、击杀数、血量、武器等级、悬赏板、面板开关、提示。
  方块数组放在 `shallowRef` 里，配一个 `revision` 计数器驱动依赖它的 computed；渲染循环每帧直接读数组，不进 Vue 的依赖追踪——
  46080 格的响应式代理会让帧率掉下去。怪物数组同理，完全放在 `GameCanvas.vue` 的普通变量里。
  `reportKill` 限制最多 3 个在飞请求，`syncPlayer` 节流 700ms 且位移 >0.05 或血量变化才发。
- `game/physics.ts`：轴分离碰撞 + 子步进（单步 ≤0.2 格），高速下落不会穿墙。**玩家和怪物共用同一个 `moveBox`**，省掉两份「穿墙」bug；
  飞行怪走同一条路径但重力传 0。`solid()` 认内容表里的 `passable` 标记（树干、树叶、荧光晶可穿过）。
- `game/mobs.ts`：怪物状态、刷怪器、AI、挥砍命中、尸体清理。
- `game/textures.ts`：带种子的 LCG 逐像素画 16×16 贴图（方块斑点/矿脉/草叶/木纹、剑、材料、怪物），
  同一份 canvas 既用于画布也导出 dataURL 给物品栏/面板当图标，零外部素材。怪物只画朝右的样子，朝左时 `translate + scale(-1,1)` 翻转。
- `game/render.ts`：天空渐变 + 太阳 + 视差云；预扫可见格收集荧光晶光源，黑暗衰减取 `min(玩家衰减, 光源衰减)`，
  再用 `globalCompositeOperation='lighter'` 画径向青色光晕；怪物有呼吸浮动、受击闪红、血条、死亡淡出；挥砍画两道扇形刀光（白 + 青）。
- `components/GameCanvas.vue`：rAF 主循环、指针/键盘输入、相机跟随与 clamp、挥砍冷却、每 900ms 补怪到上限、HUD 节流 150ms、坐标上报节流 700ms、死亡遮罩与重生。
  `setPointerCapture` 包了 try/catch：合成指针事件（自动化测试）没有活动指针会抛 NotFoundError，捕获只是增强，不该挡住挥砍。
- `components/BountyPanel.vue`：悬赏板，每秒 tick 倒计时（<60s 变红）、每 5s 拉 `/bounties`，用 `nowOffset = view.now - Date.now()` 校准服务端时钟，击杀数不够禁用交付按钮。
- `components/CraftPanel.vue`：配方列表，材料够不够标红，伤害/射程/冷却直接从 `content.weapons` 读，已拥有的剑打「已在背包」。
- 触屏按钮写同一个 `controls` 响应式对象，键盘和触屏共用一套输入；挥砍是边沿触发（按一次砍一刀），`@media (hover: hover) and (pointer: fine)` 下隐藏触屏层。

## 5. 打怪机制与「不可挖掘」带来的两个必然结论

**挥砍（`mobs.ts swing`）**：遍历活着的怪，过滤 `|dx| > 武器射程`、`|dy| > 1.6`、以及「在背后」（`|dx| > 0.7` 且符号与朝向相反），
取最近的**一只**结算伤害。一刀只中一只，既符合挥砍手感，也让服务端的击杀上报一次只有一个 key。
命中后给 0.26s 受击闪红 + 击退（`vx = 朝向*6.4`，地面怪再给 `vy = -3.2`）；血量归零就把 `dying` 设成 0.4 播死亡淡出，淡到 -1 由 `prune` 清掉。

**怪物 AI（`mobs.ts think`）**：`aggro` 半径内转向追击、速度取满，半径外按 1.2–3.6s 的节奏随机换方向游荡（35% 概率原地不动）。
地面怪被前方方块挡住或玩家在 1.2 格以上就跳（`vy = -11.4`，跳跃高度约 1.9 格，刚好翻一级台阶）；
飞行怪不吃重力，`vy = clamp(dy*1.8, ±3.6) + sin(phase)*0.8`，于是蝙蝠会俯冲到你脸的高度再飘起来。
刷怪只挑玩家两侧 22–46 格、`roomFor`（地面怪要有落脚点）或 `!hits`（飞行怪只要空间是空的）通过的列，不凭空出现在脸上也不卡进方块；
同屏上限 14 只，走远超过 110 格自动消失。

**结论一：树和荧光晶必须可穿过。** 世界不能挖，方块就永久存在。实测里玩家向右走 2 格就被一棵树堵死，30 秒推不动一步——
树干 3–4 格高、树冠更宽，跳跃高度 1.9 格根本翻不过去，480 格长地图会被树随机截成若干段。
所以内容表给 `log`/`leaves`/`glow_crystal` 标 `passable: true`，客户端 `solid()` 认这个标记：它们是风景，不是墙。

**结论二：地表必须是能走的楼梯。** 原来的地形波（三个正弦叠加）相邻列高差能到 2 格，同样跳不上去。
生成时加一句 `top = clamp(top, surface[x-1]-1, surface[x-1]+1)`，把坡度限制成一级台阶，起伏的观感还在，但从出生点能一路走到地图两头。
`WorldGeneratorTest.surfaceIsWalkableFromEndToEnd` 把这两条钉成回归测试：相邻列高差 ≤1，且地表以上只允许出现 0/树/荧光晶。

**悬赏（`game/Bounties.java`）**：沿用上一版邮局的惰性结算，**不开后台线程**。`refresh` 在每次读档/`/bounties`/`/deliver` 时：
过滤过期单 → 按标题去重 → 过滤击杀目标已不在怪物表里的旧单 → 不足 `slots`(3) 就补。
`offer` 用 `Random(seed*31+seq)` 选模板、避开上一张标题，`expiresAt = now + minutes*60_000`；序号单调递增保证单号唯一。
交货单位从「材料 N 个」换成「击杀 N 只」，扣的是 `kills` 计数，酬劳是晶核/翼膜这类合成高级剑要用的材料，把「打怪 → 攒材料 → 升剑 → 打更硬的怪」接成循环。

## 6. 测试与实测记录

- `WorldGeneratorTest`（10）：同种子同世界、地表是草+泥土、基岩封底、矿脉数量与深度顺序、出生点清空、编码/解码往返（含 480 字符地表线）、
  长地图起伏与树量比 160 格版更多、**地表可走（高差 ≤1 且地表以上只有树/荧光晶）**、荧光晶长在地表且离出生点 ≥5 格、松散方块落在实心地面上。
- `GameServiceTest`（16，`@SpringBootTest` + 内存 H2）：未知怪物拒、连点两次 `LOOT_TOO_FAST`、击杀累计与掉落进包、
  材料不足/未知配方拒、木→石→铁→钻石完整升级链、开局 3 张悬赏、交付发酬换单、击杀不够/未知单/过期单拒、
  过期单读档时被替换、旧存档（无 `playerHp`/`orderSeq`、旧标题、旧物品 key）平滑升级、坐标与血量裁剪、读档删档。
- REST 全链路联调（真实 HTTP，中文 body 用 Node fetch 发，Git Bash 的 `curl -d` 会把中文弄坏）：
  创建 480×96 世界 → 连杀史莱姆攒黏液/骨棒 → 合成木剑→石剑（武器徽章 T2）→ 拉悬赏板 → 交付「史莱姆清剿」→ 击杀数被扣、板子补新单 →
  刷新读档，血量/坐标/背包/击杀数/悬赏全部持久化；连发两次 `loot` 确认 250ms 限流生效。
- 浏览器实测（桌面，内嵌浏览器）：进入世界后顶栏武器徽章、血量条、坐标、附近怪物数、6 格物品栏、操作提示都正确；
  `E` 开锻造面板列出 4 把剑与「已在背包」标记，`F` 开悬赏板显示 3 张单的倒计时、击杀进度、酬劳，货不够时交付按钮禁用；
  控制台除 Vite HMR 外无任何报错。
- **画面像素没有目视确认过（如实说明）**：内嵌浏览器没有可视视口（`visibilityState=hidden`，截图与点击被 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE` 拒），
  `requestAnimationFrame` 一帧都不推进，游戏循环和 Canvas 渲染在这个环境里根本跑不起来（实测 1.2s 内 frames=0）。
  改用临时 Node 脚本直接 import 客户端的 `physics` / `mobs` / `render` 模块，连真实后端拉 `/api/content` 和世界，跑了 25 项校验：
  世界尺寸与方块数组长度、80 次刷怪全部合法（不卡方块、离玩家 ≥20 格、在地图内）且 5 种怪都能刷出、
  追击者 5 格内贴上玩家并造成接触伤害（4 秒内 2 次，确认 1s 冷却）、飞行怪不自由落体也不卡进地形、俯冲蝙蝠能追到玩家高度、
  徒手 6 刀杀史莱姆、一刀只中最近的一只、尸体淡出后被清理、背后砍不到、超射程砍不到、
  玩家能走能跳能被击退、`roomFor` 拒绝埋进土里的位置、**从出生点一路走到地图东端（x=474/480）和西端（x=6）**、
  `drawScene` 全路径（含怪物贴图、刀光、光照）不抛异常且确有 `drawImage`/`stroke` 调用。
  脚本是校验用的临时代码，跑完已删除，不在交付目录里。
- 移动端：内嵌浏览器无法模拟粗指针，触屏布局只验证到 CSS 媒体查询与 ≤640px 窄屏排版这一层，**没有真机实测**。

## 7. 已知限制

单人、无账号、无联机；H2 文件库单进程，同时只能跑一个后端实例；
怪物模拟与命中判定在客户端，服务端只结算「这只怪死了」，伪造击杀可以刷材料（有未知 key 与 250ms 限流两道兜底，但不是密码学保证）；
世界不可挖掘，没有熔炉/燃料/耐久/装备栏，材料只能靠打怪；怪物没有生物群系与昼夜规则，纯按玩家位置刷；
悬赏惰性结算、无后台线程，离线期间不计时推进（只在下次请求时结算过期）；
玩家位置与血量非强校验；生产部署需要把 Vite 构建产物交给后端或反向代理（当前开发态靠 Vite proxy）。
