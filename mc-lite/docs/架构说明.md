# 架构说明

## 1. 为什么这样分层

```
web (Vue3 + Canvas)          server (Spring Boot)
  渲染 / 物理 / 输入预测  ──►  规则判定 / 世界状态 / 存档
  只信服务端返回的 mutation     唯一权威：能不能挖、能不能放、能不能合成
```

- **判定放服务端**：工具等级、材料数量、够不够得着、工作台在不在旁边，这些是「游戏规则」。放前端就等于把规则交给玩家改。
  客户端也做同样的预检查，但只为了**立刻**给出红/灰提示框和进度条手感，最终结果以服务端为准。
- **物理放客户端**：重力、AABB 碰撞、跳跃每帧都要算，走 HTTP 会卡成幻灯片。服务端只保存坐标（`/move`，位移 >0.05 格且间隔 700ms 才上报），
  并对坐标做边界裁剪。代价是位置不是强校验——这是简易版有意接受的取舍，挖掘/合成判定并不依赖客户端坐标的可信度，只依赖服务端存的坐标。
- **内容表驱动**：`content.json` 是方块、物品、工具、配方的唯一来源，`ContentRegistry` 启动时读一次。
  加一种矿石或改一个配方只动 JSON；前端也从 `/api/content` 拿同一份表来画贴图和合成面板，两边不会各写一套数值。

## 2. 世界怎么存

- 内存里是 `int[] blocks`，行主序：`index = y * width + x`，0 表示空气。`World` 只负责取/放/边界/是否实心。
- 落库时一个方块编码成一个字符（`'A' + id`），160×96 的世界就是 15360 个字符，存 `@Lob` 字段。比 JSON 数组小一个数量级，读写都是 O(n) 一遍扫。
- **地表线单独存一列**（`surfaceLine`，每列一个字符）。这是修 bug 修出来的设计：
  树冠会盖在树干旁边，如果「地表」按每列第一个实心方块算，树冠就会被当成地面，天空/洞穴的分界线跟着树长歪，
  渲染上表现为树干旁边悬空的暗色矩形。把生成时的地形线持久化后，挖树、挖土都不会移动这条分界线。
- 存档实体 `WorldEntity`：名字、种子、宽高、方块串、地表线、背包 JSON、玩家坐标、时间戳。H2 文件库 `./data/mclite`，`ddl-auto=update`。

## 3. 服务端判定顺序

每个世界一把锁（`synchronized (lock(id))`），同一世界的挖/放/合成/移动串行，避免两个请求同时扣同一份材料。

- `mine`：边界 → 是不是空气 → 能不能挖（基岩 hardness<0）→ 距离 ≤5 → 工具等级 ≥ 方块 tier → 扣方块、加掉落物。
- `place`：物品存在 → 可放置 → 背包有货 → 边界 → 目标为空 → 距离 ≤5 → **不与玩家 AABB 重叠**（不能把自己封进方块里）→ 扣物品、写方块。
- `craft`：配方存在 → 需要工作台时扫描玩家周围 5 格 → 材料够 → 扣材料加产物 → 若产物是更高级的镐，提示工具等级变化。
- 距离用方块中心到玩家中心的欧氏距离，`reach=5` 写在 `application.yml`。

失败抛 `GameException(code, message)`，`ApiExceptionHandler` 统一转成 400（规则不满足）或 404（世界不存在），前端直接显示 message。

## 4. 前端结构

- `stores/game.ts`（Pinia）：世界、背包、工具等级、选中物品、模式、提示。
  方块数组放在 `shallowRef` 里**原地改**，配一个 `revision` 计数器驱动依赖它的 computed；
  渲染循环每帧直接读数组，不进 Vue 的依赖追踪——160×96 的响应式代理会让帧率掉下去。
- `game/physics.ts`：轴分离碰撞 + 子步进（单步 ≤0.2 格），高速下落不会穿墙。
- `game/textures.ts`：带种子的 LCG 逐像素画 16×16 贴图（斑点、矿脉团、草叶、木纹、工作台网格、基岩噪点、斜面高光），
  同一份 canvas 既用于画布也导出 dataURL 给物品栏/合成面板当图标，零外部素材。
- `game/render.ts`：天空渐变 + 太阳 + 视差云；地表以下按深度填洞穴底色并叠加黑暗（玩家周围有光照半径）；
  目标格高亮分四色（可挖白 / 可放绿 / 等级不够或挡住红 / 够不着灰）+ 裂纹 + 进度条。
- `components/GameCanvas.vue`：rAF 主循环、指针/键盘输入、相机跟随与 clamp、HUD 节流 150ms、坐标上报节流 700ms。
  `setPointerCapture` 包了 try/catch：合成指针事件（自动化测试）没有活动指针会抛 NotFoundError，捕获只是增强，不该挡住挖掘。
- 触屏按钮写同一个 `controls` 响应式对象，键盘和触屏共用一套输入；`@media (hover: hover) and (pointer: fine)` 下隐藏。

## 5. 测试与实测记录

- `WorldGeneratorTest`（6）：地表是草+泥土、基岩封底、矿脉数量与深度顺序、出生点清空、编码/解码往返（含地表线）、同种子同世界。
- `GameServiceTest`（11，`@SpringBootTest` + 内存 H2）：徒手挖土、等级不够拒绝、树叶/基岩、超距/非实心/越界、
  工作台缺失/材料不足/未知配方、木→石→铁→钻石完整升级链、放置规则、坐标裁剪、读档删档。
- 浏览器实测（桌面，真实点击 + 合成按键事件）：
  挖草得泥土 → 砍 3 根木头 → 面板合成木板×2 和工作台 → 放置工作台（提示翻成「工作台就在旁边」）→ 合成木镐（徽章「木镐 · T1」）
  → 下挖 6 格得泥土 5 + 石头 2 → 地下光照分层正常 → 合成面板材料计数正确 → **刷新页面后坐标、背包、挖出的竖井全部还在**；控制台无报错。
- 移动端：内嵌浏览器无法模拟粗指针（`resizeTo` 后 `matchMedia('(pointer: coarse)')` 仍为 false），
  触屏布局只验证到 CSS 媒体查询与 ≤640px 窄屏排版这一层，**没有真机实测**。

## 6. 已知限制

单人、无账号、无联机；H2 文件库单进程；没有熔炉/燃料/木棍/耐久/装备；树叶无掉落；
物理在客户端，位置非强校验；生产部署需要把 Vite 构建产物交给后端或反向代理（当前开发态靠 Vite proxy）。
