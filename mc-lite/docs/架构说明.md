# 架构说明

## 1. 为什么这样分层

```
web (Vue3 + Canvas)              server (Spring Boot)
  渲染 / 玩家与怪物模拟 / 挥砍命中 ──►  掉落表 / 合成 / 悬赏结算 / 通关标记 / 存档
  分区与巢穴判定、Boss 何时出现      唯一权威：这只怪死了给什么、够不够做剑、悬赏能不能交
```

- **经济规则放服务端**：掉落表、材料数量、配方、悬赏击杀数与酬劳，这些是「游戏规则」，放前端等于把规则交给玩家改。
- **逐帧模拟放客户端**：怪物走位/追击/接触伤害、玩家重力碰撞、挥砍命中判定每帧都要算，走 HTTP 会卡成幻灯片。
  客户端判命中后只上报一句「这只怪死了」（`POST /loot`），服务端按 `content.json` 的掉落表结算材料并累计击杀数。
  **这是本版最大的信任边界**：改客户端内存可以伪造击杀刷材料。单机本地存档没有对抗需求，所以接受这个取舍，
  服务端仍做了两道兜底——未知怪物 key 直接拒（`UNKNOWN_MOB`），两次上报间隔 <250ms 拒（`LOOT_TOO_FAST`），避免手滑或脚本一秒刷几十只。
  **分区、巢穴与 Boss 出现时机也在客户端**：服务端不知道玩家在第几区、有没有走进巢穴，
  它只认 `loot` 里的 mob key，是 Boss 就把存档标成通关。直接对后端发 `loot {mob:"overlord"}` 就能伪造通关，属于同一条边界的延伸。
- **内容表驱动**：`content.json` 是方块、物品、武器、配方、怪物、分区规则（`progression`）、悬赏档位（`bounties.tiers`）的唯一来源，
  `ContentRegistry` 启动时读一次（**改内容表要重启后端**）。
  加一种怪或调一个伤害只动 JSON；前端从 `/api/content` 拿同一份表来画贴图、算挥砍射程/冷却、算分区与巢穴、列合成与悬赏面板，两边不会各写一套数值。
  怪物表里的 `w/h/color/accent/shape/weight` 是**只给客户端用的表现与刷怪权重字段**，服务端 record 不声明它们，Jackson 直接忽略；
  服务端只用 `key/name/zone/boss/hp/damage/speed/flying/aggro/drops` 里的 `key/name/zone/boss/drops`。

## 2. 世界怎么存

- 内存里是 `int[] blocks`，行主序：`index = y * width + x`，0 表示空气。`World` 只负责取/放/边界。
- 落库时一个方块编码成一个字符（`'A' + id`），480×96 的世界就是 46080 个字符，存 `@Lob` 字段（约 45KB 文本），读写都是 O(n) 一遍扫。
- **地表线单独存一列**（`surfaceLine`，每列一个字符，480 字符刚好在 `length = 512` 限制内）。
  这是上一版修 bug 修出来的设计：树冠会盖在树干旁边，如果「地表」按每列第一个实心方块算，天空/地下的分界线会跟着树长歪。
  本版它还有第二个用途——**刷怪器直接查 `surface[x]` 就知道该列地面在哪**，不用每帧向下扫描。
- **世界不可挖掘 ⇒ 方块数组是只读的**：没有 `/mine`、`/place`，服务端也不再需要塌方、埋人顶起、工具等级、reach 这些判定，
  相关代码整段删掉而不是留开关。地下层照样生成（矿脉、沙囊、碎石、基岩），只是玩家永远到不了，属于「留着的风景」。
- 存档实体 `WorldEntity`：名字、种子、宽高、方块串、地表线、背包 JSON、击杀数 JSON（`killsJson`，`@Lob`）、玩家坐标、
  血量 `playerHp`、悬赏板 `ordersJson`、自增序号 `orderSeq`、通关标记 `cleared`、时间戳。H2 文件库 `./data/mclite`，`ddl-auto=update`。
  `orderSeq`、`playerHp`、`cleared` 故意用**可空包装类型**：旧存档没有这几列，Hibernate 对非空表 `ALTER ADD COLUMN NOT NULL` 会失败；
  可空列 + 代码侧 `null→0` / `null→满血` / `null→未通关` 才能平滑升级旧档。旧档里的旧委托标题在读档时会被 `Bounties.refresh` 当成未知目标清掉换新单。
  内容表里保留 `workbench` 方块定义同理：新版既不生成也不需要它（合成随身可做），留着只是为了让挖掘版旧档里已放置的工作台还能正常渲染。

## 3. 服务端判定顺序

每个世界一把锁（`synchronized (lock(id))`），同一世界的击杀/合成/交付/移动串行，避免两个请求同时扣同一份材料或同一份击杀数。

- `loot(mob)`：怪物 key 在表里 → 距上次上报 ≥250ms → `kills.merge(mob, +1)` → `Loot.roll` 按掉落表逐项 `chance/min/max` 掷 → 加材料
  → **若 `mob.boss()` 且存档还没通关，写下 `cleared=true` 并把 message 换成「讨伐了 XX，世界通关！」**（已通关后再杀不重复播报）→ 返回 `Mutation`。
- `craft(recipe)`：配方存在 → 材料够（`NO_MATERIAL`）→ 扣材料加产物 → 若产物是更高级的剑，武器等级自动抬升并在 message 里说明。
- `bounties()`：`Bounties.refresh` 惰性清理 + 按击杀记录补满 3 张，返回悬赏板和服务端当前时间。
- `deliver(bountyId)`：单号存在 → 未过期（`BOUNTY_EXPIRED`）→ 各怪击杀数够（`NOT_ENOUGH_KILLS`）→ 扣 `wants` 加 `reward` → 移除该单 → 补新单。
- `move(x, y, hp)`：坐标裁剪到世界范围，血量裁剪到 0..100，纯存档用，不做合法性校验。

失败抛 `GameException(code, message)`，`ApiExceptionHandler` 统一转成 400（规则不满足）或 404（世界不存在），前端直接显示 message；
`LOOT_TOO_FAST` 在前端被静默吞掉——那是挥砍冷却的正常副产物，不该弹红框打扰玩家。

## 4. 前端结构

- `stores/game.ts`（Pinia）：世界、背包、击杀数、血量、武器等级、悬赏板、面板开关、提示、通关标记 `cleared` 与一次性弹层 `victory`。
  方块数组放在 `shallowRef` 里，配一个 `revision` 计数器驱动依赖它的 computed；渲染循环每帧直接读数组，不进 Vue 的依赖追踪——
  46080 格的响应式代理会让帧率掉下去。怪物数组同理，完全放在 `GameCanvas.vue` 的普通变量里。
  `reportKill` 限制最多 3 个在飞请求，`syncPlayer` 节流 700ms 且位移 >0.05 或血量变化才发。
  `cleared` 是存档里的持久状态（顶栏徽章用），`victory` 只在「从没通关变成通关」那一次为 true，读档不弹通关界面。
  分区规则也从这里出：`progression` 直接透传内容表，`spawnColumn = floor(width/2)`，客户端只按玩家离出生点的距离算当前区。
- `game/physics.ts`：轴分离碰撞 + 子步进（单步 ≤0.2 格），高速下落不会穿墙。**玩家和怪物共用同一个 `moveBox`**，省掉两份「穿墙」bug；
  飞行怪走同一条路径但重力传 0。`solid()` 认内容表里的 `passable` 标记（树干、树叶、荧光晶可穿过）。
- `game/mobs.ts`：怪物状态、刷怪器、AI、挥砍命中、尸体清理，加上本版新增的分区与巢穴判定
  （`zoneOf` / `lairStart` / `pickForZone` / `spawnBoss` / `bossOf` / `clearBoss`，详见第 5 节）。
- `game/art.ts` + `game/mobArt.ts`：画布的公共底座（`PX=16`、带种子的 LCG、`shade` 调色）与按 `shape` 分派的怪物画师
  （slime/bat/beast/golem/wisp/boss/humanoid 七种体型）。拆出来是因为 15 种怪共用 7 套画法，全塞进 `textures.ts` 会顶破单文件行数限制。
- `game/textures.ts`：带种子的 LCG 逐像素画 16×16 贴图（方块斑点/矿脉/草叶/木纹、剑、材料），怪物贴图转手给 `mobArt`，
  同一份 canvas 既用于画布也导出 dataURL 给物品栏/面板当图标，零外部素材。怪物只画朝右的样子，朝左时 `translate + scale(-1,1)` 翻转。
- `game/playerArt.ts`：主角造型。参考图是一只黄色圆胖卡通小兽，用**椭圆 + 胶囊两种笔触**在 24×34 的虚拟格子里描述
  （头/颈/身三团叠成梨形、奶油肚皮、绿眼睛、棕手棕脚带趾头），姿势（站定挥手、走路摆臂、跳起收腿、挥砍举手张嘴）由参数算四肢端点。
  几何描述与渲染后端解耦：浏览器拿 `canvasOps` 落到主画布，校验脚本拿同一份描述光栅化成 PNG 目视比对——
  这是全项目唯一能「看见」的画面元素，内嵌浏览器没有可视视口（见第 6 节）。朝左用 `mirrorOps` 翻 x，不另画一套。
- `game/render.ts`：天空渐变 + 太阳 + 视差云；预扫可见格收集荧光晶光源，黑暗衰减取 `min(玩家衰减, 光源衰减)`，
  再用 `globalCompositeOperation='lighter'` 画径向青色光晕；怪物有呼吸浮动、受击闪红、血条、死亡淡出；挥砍画两道扇形刀光（白 + 青）。
- `components/GameCanvas.vue`：rAF 主循环、指针/键盘输入、相机跟随与 clamp、挥砍冷却、每 900ms 补怪到上限、HUD 节流 150ms、坐标上报节流 700ms、死亡遮罩与重生。
  `setPointerCapture` 包了 try/catch：合成指针事件（自动化测试）没有活动指针会抛 NotFoundError，捕获只是增强，不该挡住挥砍。
  每帧先 `updateBoss()` 再 `updateSpawns()`：Boss 只按「玩家在不在巢穴里」这一个条件增删，与普通刷怪上限互不干扰。
  HUD 多了「区域 N / 14」，Boss 在场时画面顶部另挂一条独立血条。
- `components/VictoryPanel.vue`：通关界面，列出世界名、总击杀、遇到过的怪种类数（N / 15）、当前武器，
  两个出口——「继续游荡」只关掉弹层（`cleared` 留着，顶栏徽章还在），「换个世界」回选场。
- `components/BountyPanel.vue`：悬赏板，每秒 tick 倒计时（<60s 变红）、每 5s 拉 `/bounties`，用 `nowOffset = view.now - Date.now()` 校准服务端时钟，击杀数不够禁用交付按钮。
- `components/CraftPanel.vue`：配方列表，材料够不够标红，伤害/射程/冷却直接从 `content.weapons` 读，已拥有的剑打「已在背包」。
- 样式分两份：`style.css` 是布局与基础控件，`panels.css` 是面板、Boss 血条、通关界面与提示条（单文件 ≤300 行的限制拆出来的）。
- 触屏按钮写同一个 `controls` 响应式对象，键盘和触屏共用一套输入；挥砍是边沿触发（按一次砍一刀），`@media (hover: hover) and (pointer: fine)` 下隐藏触屏层。

## 5. 打怪机制：挥砍、分区、Boss 与「不可挖掘」的两个必然结论

**挥砍（`mobs.ts swing`）**：遍历活着的怪，过滤 `|dx| > 武器射程`、`|dy| > 1.6`、以及「在背后」（`|dx| > 0.7` 且符号与朝向相反），
取最近的**一只**结算伤害。一刀只中一只，既符合挥砍手感，也让服务端的击杀上报一次只有一个 key。
命中后给 0.26s 受击闪红 + 击退（`vx = 朝向*6.4`，地面怪再给 `vy = -3.2`）；血量归零就把 `dying` 设成 0.4 播死亡淡出，淡到 -1 由 `prune` 清掉。

**怪物 AI（`mobs.ts think`）**：`aggro` 半径内转向追击、速度取满，半径外按 1.2–3.6s 的节奏随机换方向游荡（35% 概率原地不动）。
地面怪被前方方块挡住或玩家在 1.2 格以上就跳（`vy = -11.4`，跳跃高度约 1.9 格，刚好翻一级台阶）；
飞行怪不吃重力，`vy = clamp(dy*1.8, ±3.6) + sin(phase)*0.8`，于是蝙蝠会俯冲到你脸的高度再飘起来。
刷怪只挑玩家两侧 22–46 格、`roomFor`（地面怪要有落脚点）或 `!hits`（飞行怪只要空间是空的）通过的列，不凭空出现在脸上也不卡进方块；
同屏上限 14 只，走远超过 110 格自动消失。

**结论一：树和荧光晶必须可穿过。** 世界不能挖，方块就永久存在。实测里玩家向右走 2 格就被一棵树堵死，30 秒推不动一步——
树干 3–4 格高、树冠更宽，跳跃高度 1.9 格根本翻不过去，480 格长地图会被树随机截成若干段。
所以内容表给 `log`/`leaves`/`glow_crystal` 标 `passable: true`，客户端 `solid()` 认这个标记：它们是风景，不是墙。

**结论二：地表必须是能走的楼梯。** 原来的地形波（三个正弦叠加）相邻列高差能到 2 格，同样跳不上去。
生成时加一句 `top = clamp(top, surface[x-1]-1, surface[x-1]+1)`，把坡度限制成一级台阶，起伏的观感还在，但从出生点能一路走到地图两头。
`WorldGeneratorTest.surfaceIsWalkableFromEndToEnd` 把这两条钉成回归测试：相邻列高差 ≤1，且地表以上只允许出现 0/树/荧光晶。

**分区难度（`mobs.ts zoneOf` / `pickForZone`）**：15 种怪在内容表里各带一个 `zone`（0..14），`zone` 越大越硬。
玩家所在区 `zone = min(zoneCount-1, floor(|x - spawnX| / zoneWidth))`，出生点在地图正中，所以往东往西都是越走越难，
不需要额外的存档状态——难度进度完全由坐标推出，读档、重生、来回走都不会错乱。
刷怪池是「`zone <= 当前区` 的非 Boss 怪」：60%（`signatureChance`）出本区招牌怪（`zone == 当前区` 的那只），否则在池里按 `weight` 抽，
于是新区有明确的新怪登场，老怪也还会零星出现，但**永远不会刷出超区的怪**。

**Boss 巢穴（`mobs.ts lairStart` / `spawnBoss`，`GameCanvas.vue updateBoss`）**：地图最东端 `lairWidth`(36) 列是巢穴，普通刷怪直接跳过这段。
走进巢穴才 `spawnBoss`：从东墙往内找第一个能容下 Boss 体型的落脚点，**一次只有一只**，出现时弹一句「XX 从巢穴深处站起来了」；
走出巢穴就 `clearBoss` 收回（不计击杀，回来它还在）；`cleared` 为真时巢穴是空的。Boss 在场时画面顶部挂独立血条。
通关由服务端结算：客户端只上报 `loot overlord`，服务端写 `cleared=true`，前端 `apply()` 发现「从没通关变成通关」才弹通关界面。

**悬赏（`game/Bounties.java`）**：沿用上一版邮局的惰性结算，**不开后台线程**。`refresh` 在每次读档/`/bounties`/`/deliver` 时：
过滤过期单 → 按目标怪去重 → 过滤目标已不在怪物表里或已变成 Boss 的旧单 → 不足 `slots`(3) 就补。
本版悬赏单**不再读模板文案，而是从怪物表现场生成**：`pool` 优先取玩家**杀过**的非 Boss 怪（老玩家的板子上不该再出现史莱姆），
只有杀过的种类凑不满一板时，才用 `fallbackZones`(0-2) 的入门怪垫底；`offer` 按目标怪的 `zone` 取对应档位
（`count` 要猎几只、`minutes` 限时多久、`reward` 给什么），标题固定拼成「猎杀 N 只 XX」，`expiresAt = now + minutes*60_000`；
序号单调递增保证单号唯一。低档要猎 6 只给黏液兽皮，高档只猎 1 只给晶核翼膜，正好接上高级剑的配方。
`targetOf` 用「wants 是单个已知非 Boss 怪 + 档位数量对得上 + 标题与现场拼出来的一致」三重校验认单，
旧存档里的「送货：木板」这类历史标题会被判为未知，整批换掉而不是让读档崩掉。
交货扣的是 `kills` 计数，多出来的猎物留着交下一单。

## 6. 测试与实测记录

- `WorldGeneratorTest`（10）：同种子同世界、地表是草+泥土、基岩封底、矿脉数量与深度顺序、出生点清空、编码/解码往返（含 480 字符地表线）、
  长地图起伏与树量比 160 格版更多、**地表可走（高差 ≤1 且地表以上只有树/荧光晶）**、荧光晶长在地表且离出生点 ≥5 格、松散方块落在实心地面上。
- `GameServiceTest`（9，`@SpringBootTest` + 内存 H2，下面三个测试类同配置、共用同一个 Spring 上下文）：世界尺寸与空手开局、击杀掉落进包并累计、掉落表 min/max 边界、未知怪物拒与连点 `LOOT_TOO_FAST`、
  材料不足/未知配方拒、武器等级跟随背包里最好的剑、坐标与血量裁剪、读档删档、同种子同地形。
- `BountyTest`（9）：交付扣击杀发酬换单、击杀不够/未知单拒、板子恒为 3 张且未过期、过期单读档时被替换、交付过期单拒、
  旧版「送货」标题被清掉、五种种子下标题不重复、**只派玩家杀过的怪**、**档位随目标分区变（高区少猎多赏）**。
- `ProgressionTest`（4）：**15 种怪的 zone/hp/damage 单调递增且最后一个是 Boss、Boss 永不上悬赏板**、
  **打死 Boss 写下通关标记并在读档后仍在（再杀一次不重复播报）**、旧存档无 `cleared` 列按未通关兜底、通关标记不被合成/移动冲掉。
- 三个测试类共用一个 `Saves` 工具（`src/test/java/com/mclite/game/Saves.java`）：绕过服务层直接改 H2 里的 JSON 列，
  用来伪造旧存档、塞击杀数、清空悬赏板，也统一了 250ms 限流的等待。
- REST 全链路联调（真实 HTTP，中文 body 用 Node fetch 发，Git Bash 的 `curl -d` 会把中文弄坏）：
  创建 480×96 世界 → 连杀史莱姆攒黏液/骨棒 → 合成木剑→石剑（武器徽章 T2）→ 拉悬赏板 → 交付「猎杀 6 只 史莱姆」→ 击杀数被扣、板子补新单 →

## 7. 已知限制

单人、无账号、无联机；H2 文件库单进程，同时只能跑一个后端实例；
怪物模拟与命中判定在客户端，服务端只结算「这只怪死了」，伪造击杀可以刷材料（有未知 key 与 250ms 限流两道兜底，但不是密码学保证）；
分区、巢穴与 Boss 出现时机同样在客户端，服务端不校验玩家坐标是否真的在巢穴里，直接发 `loot overlord` 就能把存档标成通关；
Boss 一次只有一只，走出巢穴会被收回且不计击杀，回来还得重打；通关是「一个存档一次」的标记，没有多周目或难度选择；
内容表改了要重启后端（`ContentRegistry` 只在启动时读一次）；
世界不可挖掘，没有熔炉/燃料/耐久/装备栏，材料只能靠打怪；怪物没有生物群系与昼夜规则，只按离出生点的距离分区刷；
悬赏惰性结算、无后台线程，离线期间不计时推进（只在下次请求时结算过期）；
玩家位置与血量非强校验；生产部署需要把 Vite 构建产物交给后端或反向代理（当前开发态靠 Vite proxy）。
